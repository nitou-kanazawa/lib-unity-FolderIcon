# FolderIcon 仕様書

Unity エディタのプロジェクトウィンドウで、フォルダアイコンをカスタマイズ表示する Editor 拡張パッケージ。

- パッケージ名: `jp.nitou.foldericon`
- 対応 Unity: `6000.0` 以降
- 本書のステータス: **Draft v1.1**（実装前レビュー用）

---

## 1. 目的と方針

### 1.1 目的

プロジェクトウィンドウ上でフォルダの役割を視覚的に判別できるようにし、アセットナビゲーションを高速化する。

### 1.2 設計方針

実用性を最優先する。具体的には：

1. **ゼロコンフィグで動くこと** — パッケージをインストールした直後から、同梱のデフォルトプリセットで主要フォルダにアイコンが表示される。
2. **導線が一周すること** — 「アイコンを設定する → 表示される → 解除できる」が迷わず行えること。
3. **挙動が予測できること** — どのルールが適用されたか直感的に分かるシンプルなマッチング仕様。
4. **チームで共有できること** — カスタム設定は VCS にコミットでき、チーム全員が同じ表示を得られる。
5. **壊れないこと** — 設定が空・不正でもエディタの動作を阻害しない（例外を漏らさない）。

### 1.3 基本運用モデル

想定する使われ方を仕様の前提とする：

- **基本**: フォルダ名ベースの自動適用。デフォルトプリセットが `Scripts` / `_Scripts` / `scripts` のような表記ゆれ（大文字小文字・アンダースコアプレフィックス）を吸収して主要フォルダをカバーする。
- **例外対応**: 特定のフォルダだけ変えたい場合は右クリックで個別指定（パス完全一致）。これは名前ルールより常に優先される。
- **カスタマイズ**: 必要に応じてユーザー独自のルール・アイコンに切り替え／追加できる。

### 1.4 スコープ外（本バージョンでは実装しない）

| 項目 | 理由 / 備考 |
|------|------------|
| ワイルドカード / 正規表現マッチ | 名前正規化（§4.2）で表記ゆれは吸収できるため v1 では見送り。将来拡張 |
| パス階層パターン（`Assets/**/Tests` 等） | 同上 |
| 親フォルダからの設定継承（Hierarchical） | 挙動の予測性を損なうため見送り |
| マーカーファイル方式（`.foldericon`） | リポジトリを汚すため見送り |
| 個人設定レイヤー（UserSettings） | 将来拡張。データ構造は分離を妨げない形にしておく |
| ランタイム機能 | 不要。Editor 専用（Runtime アセンブリは削除する） |
| ファイルへのアイコン適用 | フォルダのみ対象 |

## 2. 決定事項

レビューで論点となった項目の決定を明記する。

| # | 論点 | 決定 |
|---|------|------|
| D1 | 設定の保存スコープ | **プロジェクト共有**。`ScriptableSingleton` + `FilePath(ProjectSettings/FolderIconSettings.asset)` で永続化し、VCS にコミットする運用を想定 |
| D2 | マッチング方式 | **2 種類**: ①フォルダパス完全一致（個別指定用）②フォルダ名一致（名前正規化つき）。基本運用は②、例外対応が①。ワイルドカード・正規表現は将来拡張 |
| D3 | アイコン | **デフォルトアイコン画像とデフォルト設定（プリセット）をパッケージに同梱**し、インストール直後から動作。ユーザーは任意 Texture2D によるカスタムルールへ切り替え・追加が可能 |
| D4 | プリセットとカスタムの関係 | **レイヤー方式**: ユーザールールが常にプリセットより優先。プリセット自体の ON/OFF も可能。プリセットを複製してカスタム編集の出発点にもできる |
| D5 | 主要な操作導線 | **右クリック即設定**を主導線とし、ProjectSettings のルール一覧管理を補助導線とする |
| D6 | 旧設計の扱い | `Matcher/`（`IFolderMatcher` 系）、`EntryId`、`Foundation/` は**削除**。`Pattern`/`FolderIconEntry` 系を正とし本仕様に沿って改修 |

## 3. 用語

| 用語 | 定義 |
|------|------|
| ルール（Rule） | 「マッチ条件 + アイコン」の 1 組。設定データの最小単位 |
| プリセット（Preset） | ルールの集合を保持する ScriptableObject アセット。パッケージにデフォルトプリセットを同梱 |
| ユーザールール | ユーザーがプロジェクト内で定義したルール。常にプリセットより優先 |
| 名前正規化 | フォルダ名の表記ゆれ（大文字小文字・`_` プレフィックス）を吸収する前処理（§4.2） |

## 4. マッチング仕様

### 4.1 マッチ種別

| 種別 | 対象 | 判定 | 例 |
|------|------|------|-----|
| `FolderPath` | アセットパス全体 | 完全一致（大文字小文字区別あり※） | `Assets/App/Scripts` |
| `FolderName` | フォルダ名のみ | 正規化後の完全一致（§4.2） | `Scripts`（`_Scripts`, `scripts` にもマッチ） |

※ `FolderPath` は AssetDatabase が返すパスをそのまま比較する。右クリックからの個別指定で自動生成されるため、ユーザーが手入力することは想定しない。

### 4.2 名前正規化

`FolderName` の比較は、**ルール側・フォルダ側の両方**に以下の正規化を適用した上で行う：

| 正規化 | 内容 | 既定 | 例 |
|--------|------|------|-----|
| 大文字小文字の無視 | `OrdinalIgnoreCase` で比較 | ON | `scripts` ≒ `Scripts` |
| 先頭アンダースコアの無視 | 先頭の連続する `_` を除去してから比較 | ON | `_Scripts`, `__Scripts` ≒ `Scripts` |

- 正規化オプションは**グローバル設定**（ルール個別ではない）。ProjectSettings でトグル可能。
- 正規化はマッチ判定にのみ使用し、表示や保存データは原文のまま。
- 例: ルール `Scripts` は既定設定で `Scripts` / `scripts` / `_Scripts` / `_scripts` すべてにマッチする。
- 将来拡張候補: 数字プレフィックス（`01_Scripts` → `Scripts`）の無視。`^\d+_` の形のみ対象とする（`2DAssets` などを誤変換しないため）。v1 では実装しない。

### 4.3 優先順位

複数ルールがマッチした場合、以下の順で 1 つだけ適用する：

1. **ユーザールール > プリセットルール**（レイヤー優先）
2. 同一レイヤー内では **`FolderPath` > `FolderName`**（具体的な指定ほど強い）
3. それでも同順位なら**リストの上にあるルールが優先**（ProjectSettings で並べ替え可能）

適用結果が暗黙にならないよう、右クリックの設定ウィンドウで「このフォルダに現在適用されているルールと出所（ユーザー/プリセット）」を確認できること（§7.1）。

### 4.4 判定の入出力

```
入力: フォルダのアセットパス（例 "Assets/App/Scripts"）
出力: 適用アイコン（Texture2D）または null（カスタマイズなし）
```

- 無効化されたルール（`enabled == false`）はマッチ対象外。
- アイコン未設定（null / 参照切れ）のルールはマッチ対象外。
- プリセットが OFF の場合、プリセットレイヤー全体がマッチ対象外。
- パスが `Assets/` または `Packages/` 配下のフォルダでない場合は早期リターン。

## 5. 同梱アセット仕様

### 5.1 構成

パッケージ内に以下を同梱する：

```
FolderIcon/
├── Editor/
│   ├── Icons/                      # デフォルトアイコン画像（Texture2D）
│   │   ├── folder_scripts.png
│   │   ├── folder_prefabs.png
│   │   └── ...
│   └── Presets/
│       └── DefaultPreset.asset     # デフォルトプリセット（FolderIconPreset）
```

- アイコン画像は 64x64 px 以上の PNG（グリッドビューの拡大に耐えるサイズ）。TextureImporter 設定は Editor GUI 向け（sRGB, 圧縮なし or 高品質, Read/Write 不要）。
- デフォルトプリセットはパッケージ内アセントとして**読み取り専用**の扱い（ユーザーが直接編集しない。編集したい場合は §7.2 の複製機能を使う）。

### 5.2 デフォルトプリセットの内容

主要な慣習フォルダ名をカバーする（名前正規化により `_Scripts` 等も自動対応）：

| フォルダ名 | 想定内容 |
|-----------|---------|
| Scripts | C# スクリプト |
| Scenes | シーン |
| Prefabs | プレハブ |
| Materials | マテリアル |
| Textures | テクスチャ |
| Sprites | スプライト |
| Models | 3D モデル |
| Animations | アニメーション |
| Audio / Sounds / SE / BGM | サウンド（同一アイコンを複数ルールで割当） |
| Shaders | シェーダー |
| Fonts | フォント |
| UI | UI アセット |
| Effects / VFX | エフェクト |
| Editor | エディタ拡張 |
| Resources | Resources |
| Plugins | プラグイン |
| Settings | 設定アセット |
| Docs / Documents | ドキュメント |

エイリアス（Audio / Sounds 等）は「同一アイコンを参照する複数ルール」として表現する（データモデルは単純なまま）。具体的なアイコンデザインとリストの最終版は M2 で確定する。

## 6. 描画仕様

### 6.1 フック

`EditorApplication.projectWindowItemOnGUI` を使用する。

- `EventType.Repaint` 時のみ処理する。
- Play モード中も描画する（エディタ操作は Play 中も行われるため。現行実装の `Application.isPlaying` チェックは撤廃）。

### 6.2 表示モード対応

プロジェクトウィンドウの 3 表示形態すべてに対応する：

| モード | 判定 | 描画 |
|--------|------|------|
| ツリービュー（1 カラム / 2 カラム左ペイン） | `rect.height <= 20 && rect.x <= 20` 相当 | 行頭の標準フォルダアイコン位置（16px 相当）に上書き |
| リストビュー（2 カラム右・小サイズ） | `rect.height <= 20 && rect.x > 20` | 同上 |
| グリッドビュー（2 カラム右・大サイズ） | `rect.height > 20` | サムネイル領域（`rect.width` 基準の正方形）に上書き |

描画は `GUI.DrawTexture(rect, icon, ScaleMode.ScaleToFit, alphaBlend: true)`。フォルダの標準アイコンの**上に重ね描き**する方式（背景消去はしない）。同梱アイコンは不透明で作成し、全置換に見えるようにする。カスタムアイコンにも不透明を推奨する旨をドキュメントに記載。

### 6.3 パフォーマンス

- **判定結果をキャッシュする**: `Dictionary<string(path), Texture2D>`。miss 時のみルール走査。
- キャッシュ無効化タイミング:
  - 設定変更時（ルール追加/削除/編集/並べ替え/有効切替/プリセットON・OFF/正規化オプション変更） → 全クリア
  - アセットリネーム・移動・削除時（`AssetPostprocessor.OnPostprocessAllAssets`） → 全クリア（部分無効化はしない。頻度が低く全クリアで十分）
- `FolderName` ルールは正規化済み名をキーにした `Dictionary<string, Texture2D>` に事前展開し、走査を O(1) にする（ユーザー/プリセット各レイヤー）。
- ルール走査は LINQ を使わず for ループ（Repaint 毎のアロケーション回避）。

## 7. UI 仕様

### 7.1 コンテキストメニュー（主導線）

`Assets/Set Folder Icon...`（優先度 2000、メニュー表記は英語に統一）

- フォルダ選択時のみ有効（validate ハンドラで制御）。
- 実行すると小型のユーティリティウィンドウを表示：
  - 対象フォルダのパス表示
  - **現在の適用状態**: いま適用されているアイコンと、その出所（ユーザールール / プリセット / なし）を表示
  - アイコン選択: 同梱アイコン一覧からの選択 ＋ 任意 Texture2D の `ObjectField`
  - **[適用]**: `FolderPath` 完全一致のユーザールールとして保存（既存の同パスルールがあれば上書き）
  - **[解除]**: 対象パスの `FolderPath` ユーザールールを削除（存在する場合のみ表示）。解除後はプリセット等の下位ルールに戻る
- 適用/解除の即時反映（`EditorApplication.RepaintProjectWindow()`）。
- 複数フォルダ選択時は選択中の全フォルダに同一アイコンを適用する。

### 7.2 ProjectSettings（補助導線）

`Project Settings > Folder Icon`

- 機能全体の ON/OFF トグル。
- **デフォルトプリセットの ON/OFF トグル**。
- **名前正規化オプション**（大文字小文字無視 / `_` プレフィックス無視）のトグル。
- ユーザールール一覧を **ReorderableList** で表示・編集：
  - 各行: enabled トグル / matchType / pattern / icon
  - ドラッグで並べ替え（同種別内の優先順位）
  - 追加・削除
- **[プリセットを複製してカスタム化]** ボタン: デフォルトプリセットの全ルールをユーザールールへコピーする（コピー後にプリセットを OFF にするか確認ダイアログ）。プリセットを微調整したいユーザー向けの出発点
- プリセットの内容一覧（読み取り専用）の表示。
- バリデーション警告の表示（§8.3）。
- 変更は即座に `Save()` し、判定キャッシュをクリアする。
- 検索キーワード（"folder", "icon" 等）を SettingsProvider に登録する。

### 7.3 多言語

UI 文言は**英語のみ**とする（パッケージとして配布するため。現行実装の日本語メニューは置き換え）。

## 8. データ仕様

### 8.1 永続化

- ユーザー設定: `ScriptableSingleton<FolderIconSettings>` + `[FilePath("ProjectSettings/FolderIconSettings.asset", Location.ProjectFolder)]`
- テキストシリアライズされ、アイコンへの参照は GUID で保持される。同梱アイコンはパッケージ内アセットなので、どのプロジェクトでも GUID 参照が有効。
- **チーム共有のため VCS にコミットする**ことを README に明記する。
- デフォルトプリセット: パッケージ内の `FolderIconPreset`（ScriptableObject アセット）。
- 現行の `ProjectSettings/Nitou/FolderIcon.dat` は廃止（後方互換は取らない。v1.0 到達前のため）。

### 8.2 データモデル

```csharp
enum FolderMatchType { FolderPath, FolderName }

[Serializable]
class FolderIconRule
{
    bool            enabled = true;
    FolderMatchType matchType;
    string          pattern;      // パス or フォルダ名
    Texture2D       icon;
}

// パッケージ同梱プリセット（将来ユーザー作成プリセットにも流用可能）
class FolderIconPreset : ScriptableObject
{
    List<FolderIconRule> rules;
}

// プロジェクト設定（ScriptableSingleton）
class FolderIconSettings : ScriptableSingleton<FolderIconSettings>
{
    bool                 isEnabled = true;          // 機能全体の ON/OFF
    bool                 useDefaultPreset = true;   // プリセットレイヤーの ON/OFF
    bool                 ignoreCase = true;         // 名前正規化: 大文字小文字
    bool                 ignoreLeadingUnderscore = true; // 名前正規化: _ プレフィックス
    List<FolderIconRule> userRules;                 // null 不可。デシリアライズ後に必ず non-null を保証
    int                  version = 1;               // 将来のマイグレーション用
}
```

- **null 安全**: `userRules` は `OnEnable` で null なら生成する（現行の `_entryStore` 未初期化 NRE を修正）。
- デフォルトプリセットのロードはパッケージパス（`Packages/jp.nitou.foldericon/...`）から `AssetDatabase.LoadAssetAtPath` で行い、失敗時はプリセットなしとして動作継続。
- `version` フィールドをデータに含め、将来フォーマット変更時のマイグレーションを可能にする。

### 8.3 バリデーション

| 状態 | 扱い |
|------|------|
| `pattern` が空 | マッチ対象外（エラーにしない）。UI 上で警告表示 |
| `icon` が null（参照切れ含む） | マッチ対象外。UI 上で警告表示 |
| 同一 `matchType` + 正規化後 `pattern` の重複 | 許容する（上優先ルールが勝つ）。UI 上で情報表示 |

## 9. エラー処理・堅牢性

- `projectWindowItemOnGUI` ハンドラ内は例外を外に漏らさない（描画毎のログ洪水を防ぐため、同一例外は初回のみ `Debug.LogException`）。
- 不正なパターンや参照切れアイコンがあっても他のルールの動作に影響しない。
- 設定ファイルが手動編集などで壊れていた場合、既定値（空ユーザールール・機能 ON・プリセット ON）で起動する。
- デフォルトプリセットのロード失敗（パッケージ構成の破損等）はユーザールールのみで動作継続。

---

## 10. 将来拡張（本仕様では設計余地のみ確保）

優先度順：

1. **ワイルドカード / 正規表現マッチ**: `FolderMatchType` に列挙子を追加する形で拡張。優先順位は `FolderPath > FolderName > NamePattern > Regex` とする想定
2. **数字プレフィックス正規化**: `01_Scripts` → `Scripts`（§4.2）
3. **ユーザー作成プリセット**: `FolderIconPreset` アセットをユーザーが作成し、設定から差し替え・複数適用できるようにする
4. **個人設定レイヤー**: `UserSettings/` 配下に同スキーマの上書きストアを追加（優先順位はユーザールールとプリセットの間 or 最上位を検討）
5. **インポート / エクスポート**: ルールセットの JSON 入出力（チーム間・プロジェクト間の移送用）
6. サブアイコン（ツリービューで標準アイコンの右に小さく併記）
